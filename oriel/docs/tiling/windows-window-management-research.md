# Windows window-management research

This document inventories the Windows-originated events and messages handled by
GlazeWM. It is intended as implementation context for future LLM sessions
working on Oriel's Windows tiling behavior.

## Research baseline and scope

- Upstream repository: [`glzr-io/glazewm`](https://github.com/glzr-io/glazewm)
- Inspected revision:
  [`5709ad0a3c7c386bbc3e38166a865ffc12937515`](https://github.com/glzr-io/glazewm/tree/5709ad0a3c7c386bbc3e38166a865ffc12937515)
- Windows adapter:
  [`packages/wm-platform/src/platform_impl/windows`](https://github.com/glzr-io/glazewm/tree/5709ad0a3c7c386bbc3e38166a865ffc12937515/packages/wm-platform/src/platform_impl/windows)
- WM event consumers:
  [`packages/wm/src/events`](https://github.com/glzr-io/glazewm/tree/5709ad0a3c7c386bbc3e38166a865ffc12937515/packages/wm/src/events)

"Event" below means an OS-originated WinEvent callback, hook callback, raw-input
message, or window message that GlazeWM explicitly handles. Internal Rust
events are shown only to explain the OS-to-application mapping.

GlazeWM has four Windows event ingress mechanisms:

1. `SetWinEventHook` for window lifecycle, focus, and geometry.
2. `SetWindowsHookExW(WH_KEYBOARD_LL)` for global keybindings.
3. `RegisterRawInputDevices` plus `WM_INPUT` for global mouse input.
4. A hidden message window for display, device, settings, and power messages.

## WinEvent callback contract

[Registration and callback source](https://github.com/glzr-io/glazewm/blob/5709ad0a3c7c386bbc3e38166a865ffc12937515/packages/wm-platform/src/platform_impl/windows/window_listener.rs)

GlazeWM installs six `SetWinEventHook` ranges:

```text
EVENT_OBJECT_DESTROY        .. EVENT_OBJECT_HIDE
EVENT_SYSTEM_MINIMIZESTART  .. EVENT_SYSTEM_MINIMIZEEND
EVENT_SYSTEM_MOVESIZESTART  .. EVENT_SYSTEM_MOVESIZEEND
EVENT_SYSTEM_FOREGROUND     .. EVENT_SYSTEM_FOREGROUND
EVENT_OBJECT_LOCATIONCHANGE .. EVENT_OBJECT_NAMECHANGE
EVENT_OBJECT_CLOAKED        .. EVENT_OBJECT_UNCLOAKED
```

Every range uses:

```text
idProcess = 0
idThread  = 0
flags     = WINEVENT_OUTOFCONTEXT | WINEVENT_SKIPOWNPROCESS
```

This observes all processes and threads, queues callbacks onto GlazeWM's own
event-loop thread, avoids DLL injection, and excludes events generated by
GlazeWM itself.

The callback receives:

| Argument | Meaning and GlazeWM use |
|---|---|
| `hook: HWINEVENTHOOK` | Hook handle; unused. |
| `event_type: u32` | One of the `EVENT_*` constants below; selects the internal event. |
| `handle: HWND` | Window that generated the event; converted to GlazeWM's `WindowId`/native window wrapper. |
| `id_object: i32` | Accessible object identifier. GlazeWM requires `OBJID_WINDOW`. |
| `id_child: i32` | Child identifier. GlazeWM requires `0`, meaning the object itself. |
| `event_thread: u32` | ID of the thread that generated the event; unused. |
| `event_time: u32` | Event time in milliseconds; unused. |

All WinEvents are discarded unless `id_object == OBJID_WINDOW`,
`id_child == 0`, and `handle != NULL`. This excludes UI controls, menus,
tooltips, and invalid window handles.

Microsoft reference:
[`SetWinEventHook`](https://learn.microsoft.com/windows/win32/api/winuser/nf-winuser-setwineventhook)
and [event constants](https://learn.microsoft.com/windows/win32/winauto/event-constants).

## Window events

### How GlazeWM detects new windows

GlazeWM does **not** subscribe to `EVENT_OBJECT_CREATE`. A create notification
can arrive before a window has finished establishing the visibility, styles,
title, and geometry needed for management decisions. Instead, GlazeWM treats
`EVENT_OBJECT_SHOW` and `EVENT_OBJECT_UNCLOAKED` as the signals that a new or
returning window is ready to evaluate. Windows that already exist when GlazeWM
starts are discovered through startup enumeration.

### `EVENT_OBJECT_DESTROY` (`0x8001`)

- **Triggered:** An accessible object is destroyed. GlazeWM's common filter
  limits this to a top-level window; the `HWND` identifies the old window but
  must no longer be treated as a usable native window.
- **Arguments used:** `event_type`, `handle`, `id_object`, and `id_child`.
- **Internal mapping:** `WindowEvent::Destroyed`.
- **Purpose:** Find the managed window by ID and unmanage it. If its workspace
  becomes empty and is not configured to stay alive, deactivate that workspace.
- **Consumer:** [`handle_window_destroyed.rs`](https://github.com/glzr-io/glazewm/blob/5709ad0a3c7c386bbc3e38166a865ffc12937515/packages/wm/src/events/handle_window_destroyed.rs)

### `EVENT_OBJECT_SHOW` (`0x8002`)

- **Triggered:** A previously hidden window becomes visible.
- **Arguments used:** The filtered `HWND` is wrapped as a native window.
- **Internal mapping:** `WindowEvent::Shown`.
- **Purpose:** Complete GlazeWM's own `Showing -> Shown` display-state
  transition. Otherwise, manage the newly visible window unless an ignore rule
  matches.
- **Consumer:** [`handle_window_shown.rs`](https://github.com/glzr-io/glazewm/blob/5709ad0a3c7c386bbc3e38166a865ffc12937515/packages/wm/src/events/handle_window_shown.rs)

### `EVENT_OBJECT_HIDE` (`0x8003`)

- **Triggered:** A visible window is hidden.
- **Arguments used:** The filtered `HWND`.
- **Internal mapping:** `WindowEvent::Hidden`.
- **Purpose:** Complete GlazeWM's own `Hiding -> Hidden` transition without
  unmanaging during a workspace switch. For an otherwise shown window, unmanage
  it only after native visibility confirms it is actually hidden; this protects
  against stale or out-of-order notifications.
- **Consumer:** [`handle_window_hidden.rs`](https://github.com/glzr-io/glazewm/blob/5709ad0a3c7c386bbc3e38166a865ffc12937515/packages/wm/src/events/handle_window_hidden.rs)

### `EVENT_OBJECT_CLOAKED` (`0x8017`)

- **Triggered:** DWM cloaks a window without changing its ordinary visibility,
  commonly when it moves to another Windows virtual desktop.
- **Arguments used:** The filtered `HWND`.
- **Internal mapping:** `WindowEvent::Hidden`.
- **Purpose:** Uses the same hidden-window path as `EVENT_OBJECT_HIDE`.
- **Consumer:** [`handle_window_hidden.rs`](https://github.com/glzr-io/glazewm/blob/5709ad0a3c7c386bbc3e38166a865ffc12937515/packages/wm/src/events/handle_window_hidden.rs)

### `EVENT_OBJECT_UNCLOAKED` (`0x8018`)

- **Triggered:** DWM makes a cloaked window available again.
- **Arguments used:** The filtered `HWND`.
- **Internal mapping:** `WindowEvent::Shown`.
- **Purpose:** Uses the same shown-window path as `EVENT_OBJECT_SHOW`, allowing
  the window to complete a display transition or become managed.
- **Consumer:** [`handle_window_shown.rs`](https://github.com/glzr-io/glazewm/blob/5709ad0a3c7c386bbc3e38166a865ffc12937515/packages/wm/src/events/handle_window_shown.rs)

### `EVENT_SYSTEM_MINIMIZESTART` (`0x0016`)

- **Triggered:** A window begins being minimized.
- **Arguments used:** The filtered `HWND`; GlazeWM verifies the current state
  with `IsIconic`.
- **Internal mapping:** `WindowEvent::Minimized`.
- **Purpose:** Change the managed state to minimized, cancel an active drag,
  choose another container to focus, and record a timestamp used by the
  100 ms post-minimize focus correction.
- **Consumer:** [`handle_window_minimized.rs`](https://github.com/glzr-io/glazewm/blob/5709ad0a3c7c386bbc3e38166a865ffc12937515/packages/wm/src/events/handle_window_minimized.rs)

### `EVENT_SYSTEM_MINIMIZEEND` (`0x0017`)

- **Triggered:** A minimized window finishes being restored.
- **Arguments used:** The filtered `HWND`; GlazeWM verifies that `IsIconic` is
  now false.
- **Internal mapping:** `WindowEvent::MinimizeEnded`.
- **Purpose:** Restore the window's previous managed state, or the configured
  default state if no previous state exists.
- **Consumer:** [`handle_window_minimize_ended.rs`](https://github.com/glzr-io/glazewm/blob/5709ad0a3c7c386bbc3e38166a865ffc12937515/packages/wm/src/events/handle_window_minimize_ended.rs)

### `EVENT_SYSTEM_MOVESIZESTART` (`0x000A`)

- **Triggered:** The user starts an interactive move or resize through the
  system move/size loop.
- **Arguments used:** The filtered `HWND`.
- **Internal mapping:** `WindowEvent::MovedOrResized` with
  `is_interactive_start = true` and `is_interactive_end = false`.
- **Purpose:** Record the initial frame and begin drag detection. Once movement
  reaches GlazeWM's 10-pixel threshold, the managed window can transition to
  floating.
- **Consumer:** [`handle_window_moved_or_resized.rs`](https://github.com/glzr-io/glazewm/blob/5709ad0a3c7c386bbc3e38166a865ffc12937515/packages/wm/src/events/handle_window_moved_or_resized.rs)

### `EVENT_SYSTEM_MOVESIZEEND` (`0x000B`)

- **Triggered:** The user exits the interactive move/size loop.
- **Arguments used:** The filtered `HWND`.
- **Internal mapping:** `WindowEvent::MovedOrResized` with
  `is_interactive_start = false` and `is_interactive_end = true`.
- **Purpose:** Finalize the drag. Depending on position and target, GlazeWM
  snaps/reorders the window in the tiling tree or preserves its floating
  placement.
- **Consumer:** [`handle_window_moved_or_resized.rs`](https://github.com/glzr-io/glazewm/blob/5709ad0a3c7c386bbc3e38166a865ffc12937515/packages/wm/src/events/handle_window_moved_or_resized.rs)

### `EVENT_SYSTEM_FOREGROUND` (`0x0003`)

- **Triggered:** The system foreground window changes.
- **Arguments used:** The filtered foreground `HWND`.
- **Internal mapping:** `WindowEvent::Focused`.
- **Purpose:** Synchronize native and WM focus, update the focused descendant,
  run focus-triggered window rules, emit `WmEvent::FocusChanged`, and switch to
  a hidden workspace if Windows foregrounded one of its windows.
- **Suppression/correction:** Ignore windows transitioning to hidden. Within
  100 ms of unmanaging or minimizing, GlazeWM may reassert its intended focus
  to avoid Windows' transient focus choice.
- **Consumer:** [`handle_window_focused.rs`](https://github.com/glzr-io/glazewm/blob/5709ad0a3c7c386bbc3e38166a865ffc12937515/packages/wm/src/events/handle_window_focused.rs)

### `EVENT_OBJECT_LOCATIONCHANGE` (`0x800B`)

- **Triggered:** A window's location, size, or shape changes. This can be
  generated repeatedly during interactive and programmatic moves.
- **Arguments used:** The filtered `HWND`; GlazeWM obtains the current frame
  with `DwmGetWindowAttribute(DWMWA_EXTENDED_FRAME_BOUNDS)` and separately
  checks maximized/minimized state.
- **Internal mapping:** `WindowEvent::MovedOrResized` with both interactive
  flags false.
- **Purpose:** Detect geometry, maximized, and fullscreen changes; update
  floating placement; and update an in-progress drag operation.
- **Suppression:** Ignore minimized windows. Ignore the event when frame and
  maximized state are unchanged, except where an interactive-start transition
  still needs processing. This deduplication is important because the event is
  high frequency.
- **Consumer:** [`handle_window_moved_or_resized.rs`](https://github.com/glzr-io/glazewm/blob/5709ad0a3c7c386bbc3e38166a865ffc12937515/packages/wm/src/events/handle_window_moved_or_resized.rs)

### `EVENT_OBJECT_NAMECHANGE` (`0x800C`)

- **Triggered:** A window's accessible name changes; for `OBJID_WINDOW`, this
  normally means its title changed.
- **Arguments used:** The filtered `HWND`; the title is then read with
  `GetWindowTextW`.
- **Internal mapping:** `WindowEvent::TitleChanged`.
- **Purpose:** Refresh the cached native title and evaluate window rules
  configured for `WindowRuleEvent::TitleChange`.
- **Consumer:** [`handle_window_title_changed.rs`](https://github.com/glzr-io/glazewm/blob/5709ad0a3c7c386bbc3e38166a865ffc12937515/packages/wm/src/events/handle_window_title_changed.rs)

## Low-level keyboard events

[Hook source](https://github.com/glzr-io/glazewm/blob/5709ad0a3c7c386bbc3e38166a865ffc12937515/packages/wm-platform/src/platform_impl/windows/keyboard_hook.rs)

GlazeWM installs a system-wide `WH_KEYBOARD_LL` (`13`) hook:

```text
SetWindowsHookExW(WH_KEYBOARD_LL, hook_proc, NULL, 0)
```

The `LowLevelKeyboardProc` arguments are:

| Argument | Meaning and GlazeWM use |
|---|---|
| `code: i32` | Only `HC_ACTION` (`0`) is processed. Negative values are immediately passed to `CallNextHookEx`. |
| `wparam: WPARAM` | Key message: `WM_KEYDOWN`, `WM_KEYUP`, `WM_SYSKEYDOWN`, or `WM_SYSKEYUP`. |
| `lparam: LPARAM` | Pointer to `KBDLLHOOKSTRUCT`. GlazeWM reads `vkCode`; scan code, flags, time, and extra info are unused. |

Modifier state is queried with `GetKeyState` for left/right Win, Alt, Control,
and Shift. The callback must remain fast because it synchronously participates
in system keyboard processing.

| Message | Value | Trigger | GlazeWM use |
|---|---:|---|---|
| `WM_KEYDOWN` | `0x0100` | A non-system key is pressed. | Evaluate a keybinding as a keypress. |
| `WM_SYSKEYDOWN` | `0x0104` | A system key is pressed, typically while Alt is down or for F10. | Evaluate a keybinding as a keypress. |
| `WM_KEYUP` | `0x0101` | A non-system key is released. | Observed by the hook but not treated as a keypress. |
| `WM_SYSKEYUP` | `0x0105` | A system key is released. | Observed by the hook but not treated as a keypress. |

When the application callback reports a matching keybinding, the hook returns
`LRESULT(1)` to consume the event. Otherwise it calls `CallNextHookEx`.

Microsoft reference:
[`LowLevelKeyboardProc`](https://learn.microsoft.com/windows/win32/winmsg/lowlevelkeyboardproc)
and [`KBDLLHOOKSTRUCT`](https://learn.microsoft.com/windows/win32/api/winuser/ns-winuser-kbdllhookstruct).

## Raw mouse input

[Listener source](https://github.com/glzr-io/glazewm/blob/5709ad0a3c7c386bbc3e38166a865ffc12937515/packages/wm-platform/src/platform_impl/windows/mouse_listener.rs)

GlazeWM registers usage page `0x01` (generic desktop), usage `0x02` (mouse)
with `RIDEV_INPUTSINK`, targeting its hidden message window. It therefore
receives mouse input while not foreground. Deregistration uses `RIDEV_REMOVE`
and a null target.

### `WM_INPUT` (`0x00FF`)

- **Triggered:** Raw input is available from a registered device.
- **WndProc arguments:** `wparam` describes whether input arrived while the app
  was foreground or in the input sink; GlazeWM does not use it. `lparam` is an
  `HRAWINPUT` passed to `GetRawInputData(..., RID_INPUT, ...)`.
- **Filtering:** Ignore invalid/overflowing reads, non-mouse packets, and
  packets whose `ulExtraInformation` equals GlazeWM's
  `FOREGROUND_INPUT_IDENTIFIER`. The last case prevents synthetic focus clicks
  sent by GlazeWM from feeding back into its mouse logic.
- **Button decoding:**

| Raw flag | Value | Internal kind |
|---|---:|---|
| `RI_MOUSE_LEFT_BUTTON_DOWN` | `0x0001` | `LeftButtonDown` |
| `RI_MOUSE_LEFT_BUTTON_UP` | `0x0002` | `LeftButtonUp` |
| `RI_MOUSE_RIGHT_BUTTON_DOWN` | `0x0004` | `RightButtonDown` |
| `RI_MOUSE_RIGHT_BUTTON_UP` | `0x0008` | `RightButtonUp` |
| No recognized button flag | - | `Move` |

- **Purpose:** Feed focus-follows-mouse and drag behavior. Position is sampled
  with `GetCursorPos`; GlazeWM does not use the raw relative movement as the
  final cursor position.
- **Throttling:** Button events are immediate. Move events are emitted at most
  once every 50 ms.

Microsoft reference:
[`WM_INPUT`](https://learn.microsoft.com/windows/win32/inputdev/wm-input),
[`RegisterRawInputDevices`](https://learn.microsoft.com/windows/win32/api/winuser/nf-winuser-registerrawinputdevices),
and [`GetRawInputData`](https://learn.microsoft.com/windows/win32/api/winuser/nf-winuser-getrawinputdata).

## Hidden message-window events

[Event-loop source](https://github.com/glzr-io/glazewm/blob/5709ad0a3c7c386bbc3e38166a865ffc12937515/packages/wm-platform/src/platform_impl/windows/event_loop.rs)
and
[display-listener source](https://github.com/glzr-io/glazewm/blob/5709ad0a3c7c386bbc3e38166a865ffc12937515/packages/wm-platform/src/platform_impl/windows/display_listener.rs)

GlazeWM creates a hidden `OVERLAPPEDWINDOW` with class name `MessageWindow`.
Its WndProc receives `WM_INPUT` and the following display/power messages.

### `WM_DISPLAYCHANGE` (`0x007E`)

- **Triggered:** The display resolution changes.
- **Arguments:** `wparam` is the new bits per pixel; `LOWORD(lparam)` and
  `HIWORD(lparam)` are the new width and height. GlazeWM ignores all three.
- **Purpose:** Emit `PlatformEvent::DisplaySettingsChanged`, reconcile WM
  monitors with OS monitors, reposition floating windows where needed, and
  redraw.
- **Suppression:** Ignored while GlazeWM considers the system suspended.
- **Consumer:** [`handle_display_settings_changed.rs`](https://github.com/glzr-io/glazewm/blob/5709ad0a3c7c386bbc3e38166a865ffc12937515/packages/wm/src/events/handle_display_settings_changed.rs)
- **Microsoft reference:** [`WM_DISPLAYCHANGE`](https://learn.microsoft.com/windows/win32/gdi/wm-displaychange).

### `WM_SETTINGCHANGE` (`0x001A`)

- **Triggered:** A system-wide setting changes, normally through
  `SystemParametersInfo`.
- **Arguments:** `wparam` identifies the `SPI_*` action; `lparam` can point to
  a setting-name string and is ignored.
- **Filter:** Only `wparam == SPI_SETWORKAREA` (`0x002F`) is relevant. Taskbars,
  appbars, and third-party taskbar tools can alter the work area this way.
- **Purpose:** Emit `PlatformEvent::DisplaySettingsChanged` and perform the
  same monitor/work-area reconciliation as `WM_DISPLAYCHANGE`.
- **Suppression:** Ignored while suspended.
- **Consumer:** [`handle_display_settings_changed.rs`](https://github.com/glzr-io/glazewm/blob/5709ad0a3c7c386bbc3e38166a865ffc12937515/packages/wm/src/events/handle_display_settings_changed.rs)
- **Microsoft reference:** [`WM_SETTINGCHANGE`](https://learn.microsoft.com/windows/win32/winmsg/wm-settingchange).

### `WM_DEVICECHANGE` (`0x0219`)

- **Triggered:** Hardware or a device configuration changes.
- **Arguments:** `wparam` is a `DBT_*` device event code; `lparam` may point to
  event-specific data and is unused.
- **Filter:** Only `DBT_DEVNODES_CHANGED` (`0x0007`) is accepted. This can be
  broader than display-only changes; upstream contains a TODO questioning
  whether this message is needed.
- **Purpose:** Emit `PlatformEvent::DisplaySettingsChanged` and reconcile
  monitors.
- **Suppression:** Ignored while suspended.
- **Consumer:** [`handle_display_settings_changed.rs`](https://github.com/glzr-io/glazewm/blob/5709ad0a3c7c386bbc3e38166a865ffc12937515/packages/wm/src/events/handle_display_settings_changed.rs)
- **Microsoft reference:** [`WM_DEVICECHANGE`](https://learn.microsoft.com/windows/win32/devio/wm-devicechange).

### `WM_POWERBROADCAST` (`0x0218`)

- **Triggered:** The system broadcasts a power-management transition.
- **Arguments:** `wparam` is a `PBT_*` event code. `lparam` is
  event-dependent and unused for the handled events.
- **Handled values:**

| `wparam` | Value | Trigger and use |
|---|---:|---|
| `PBT_APMSUSPEND` | `0x0004` | The machine is entering suspend/hibernate; set `is_system_suspended = true`. |
| `PBT_APMRESUMEAUTOMATIC` | `0x0012` | The machine resumed automatically; clear the suspended flag. |
| `PBT_APMRESUMESUSPEND` | `0x0015` | The machine resumed in response to user activity; clear the suspended flag. |

Other power codes are ignored. The callback returns `0` for all
`WM_POWERBROADCAST` messages. The flag suppresses display reconciliation while
the OS display topology is transient during suspend/resume.

Microsoft reference:
[`WM_POWERBROADCAST`](https://learn.microsoft.com/windows/win32/power/wm-powerbroadcast).

## Internal Windows messages, not external events

These messages appear in the Windows adapter but should not be mistaken for
external event sources:

- `GlazeWM:Dispatch` is registered with `RegisterWindowMessageW` and used with
  `PostMessageW`/`SendMessageW` to marshal GlazeWM closures onto the event-loop
  thread.
- `WM_QUIT` (`0x0012`) is posted by GlazeWM with `PostThreadMessageW` during
  shutdown so `GetMessageW` exits.

## Important design lessons for Oriel

1. Use `WINEVENT_OUTOFCONTEXT` and keep a message loop on the registering
   thread. Delivery is asynchronous and serialized on that thread.
2. Filter every accessibility callback by `OBJID_WINDOW`, `CHILDID_SELF`, and
   non-null `HWND`; otherwise child-control noise is substantial.
3. Treat show/hide and cloak/uncloak as paired visibility channels. Cloaking is
   especially relevant to Windows virtual desktops.
4. Do not infer minimized state solely from event ordering; validate with
   `IsIconic`.
5. Deduplicate `EVENT_OBJECT_LOCATIONCHANGE`. It is high frequency and fires
   for programmatic as well as user-driven geometry changes.
6. Model interactive start, intermediate geometry changes, and interactive end
   separately. They carry different intent.
7. Expect focus notifications around close/minimize to be transient and
   potentially contrary to the WM's intended focus.
8. Gate monitor reconciliation during suspend/resume because display messages
   arrive while topology is unstable.
9. Tag synthetic input and reject the tag at the input listener to prevent
   feedback loops.

## Python/Win32 interop requirements

The event inventory is enough to reproduce basic GlazeWM-style reactions, but a
reliable Python implementation also needs the following native interop details.

### Hook declarations and lifetimes

- Declare exact `ctypes` `argtypes` and `restype` values for
  `SetWinEventHook`, `UnhookWinEvent`, `SetWindowsHookExW`,
  `CallNextHookEx`, raw-input APIs, and every other directly invoked Win32
  function.
- Define callbacks with `WINFUNCTYPE` and the correct calling convention.
- Use pointer-width-safe types for `HWND`, `HANDLE`, `WPARAM`, `LPARAM`,
  `LRESULT`, and callback return values. Do not assume handles fit in 32 bits.
- Retain strong references to callback objects and hook handles for the full
  registration lifetime; otherwise Python can garbage-collect a callback still
  held by Windows.
- Unhook every successfully installed hook and deregister raw-input devices
  during deterministic shutdown.

### Message-loop and threading model

- Register out-of-context WinEvent hooks on the same thread that owns and pumps
  the Windows message queue.
- Run `GetMessageW`, `TranslateMessage`, and `DispatchMessageW` continuously;
  `WINEVENT_OUTOFCONTEXT` delivery depends on that loop.
- Keep window-manager state single-writer. Marshal work from IPC, timers, and
  worker threads onto the message-loop thread with a private `WM_APP` message
  and `PostThreadMessageW`/`PostMessageW`.
- Keep synchronous low-level keyboard callbacks short and always call
  `CallNextHookEx` when an event is not intentionally consumed.
- Preserve callback references until after hooks are removed and queued
  callbacks can no longer execute.

### Window identity and event validation

- Filter accessibility callbacks to `OBJID_WINDOW`, `CHILDID_SELF`, and a
  non-null `HWND`.
- Validate handles with `IsWindow` before APIs that require a live window.
  `EVENT_OBJECT_DESTROY` supplies an identity for lookup, not a handle that is
  safe to inspect.
- Treat an `HWND` as an opaque identifier whose numeric value Windows may
  eventually reuse. Remove destroyed windows promptly.
- Enumerate existing top-level windows with `EnumWindows` before relying on
  incremental events.
- Distinguish "created" from "ready to manage": evaluate candidates on
  `EVENT_OBJECT_SHOW`/`EVENT_OBJECT_UNCLOAKED`, not merely on object creation.

### Manageability and native state

- Combine `IsWindow`, `IsWindowVisible`, `IsIconic`, ownership, parent, style,
  extended-style, and cloaking checks to decide whether a top-level window
  should be managed.
- Read DWM cloaking state with
  `DwmGetWindowAttribute(DWMWA_CLOAKED)` when virtual desktops matter.
- Recheck candidates after later show, foreground, title, or location events;
  some applications establish styles and metadata asynchronously.
- Expect duplicate and out-of-order lifecycle notifications. Make show/hide,
  minimize/restore, and manage/unmanage operations idempotent.

### DPI and geometry

- Set process DPI awareness before enumerating monitors or reading any window
  rectangles. Mixing logical and physical coordinates corrupts tiling math.
- Prefer `DwmGetWindowAttribute(DWMWA_EXTENDED_FRAME_BOUNDS)` for the visible
  frame. `GetWindowRect` can include invisible resize borders.
- Use `GetMonitorInfoW`, `MonitorFromWindow`, `MonitorFromPoint`, and
  `EnumDisplayMonitors` consistently in the same coordinate space.
- Account for work areas, taskbars/appbars, negative coordinates, per-monitor
  DPI, and monitors positioned above or left of the primary display.
- Deduplicate `EVENT_OBJECT_LOCATIONCHANGE` by comparing the newly observed
  frame and state with the cached values before mutating layout state.

### Raw input and keyboard structures

- Define `RAWINPUTDEVICE`, `RAWINPUTHEADER`, `RAWMOUSE`, `RAWINPUT`, and their
  unions with Windows-compatible packing and field widths.
- Call `GetRawInputData` first to obtain the required size, allocate the
  buffer, then call it again with `RID_INPUT`; reject failed or truncated
  reads.
- Register mouse input with the hidden message window as `hwndTarget` and use
  `RIDEV_INPUTSINK` only when background input is required.
- Define and decode `KBDLLHOOKSTRUCT`; distinguish key-down from key-up using
  the hook's `wparam`, and query left/right modifier keys explicitly.
- Tag synthetic `SendInput` packets through `dwExtraInfo` and filter the tag
  from raw-input processing to prevent feedback loops.

### Hidden WndProc and system messages

- Register a window class and create a hidden message-only or non-visible
  window whose WndProc remains alive for the process lifetime.
- Decode `WM_SETTINGCHANGE`, `WM_DEVICECHANGE`, and `WM_POWERBROADCAST`
  `wparam` values before reacting; most variants are unrelated to monitor
  layout.
- Suppress monitor reconciliation between `PBT_APMSUSPEND` and a matching
  resume event because display topology is transient during power changes.
- Return the documented result for handled messages and call `DefWindowProcW`
  for messages not consumed by the application.

### Errors and cleanup

- Set and inspect Win32 last-error values where the API contract supports
  them. A null handle or zero result is not always an error, so follow each
  function's documented ambiguity rules.
- Surface registration failures instead of running with only part of the event
  model active.
- Track which hooks, devices, classes, and windows were successfully created
  so partial initialization can unwind safely.
- Ensure shutdown wakes and terminates the message loop, unregisters native
  resources in reverse order, and does not leave timers posting to a dead
  thread.

## Events, APIs, and hooks verified absent

At the inspected revision, exhaustive upstream searches found no use of:

- `EVENT_OBJECT_CREATE`
- `RegisterShellHookWindow` / `WH_SHELL`
- `WH_CBT`
- `WH_MOUSE` / `WH_MOUSE_LL`
- `RegisterHotKey` / `WM_HOTKEY`
- `SHChangeNotifyRegister`
- `WM_COPYDATA`

GlazeWM uses WinEvent hooks instead of shell/CBT hooks, raw input instead of a
mouse hook, a low-level keyboard hook instead of `RegisterHotKey`, and named
pipes rather than `WM_COPYDATA` for IPC.
